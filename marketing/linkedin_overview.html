THE PROBLEM

Four teams, four dashboards, one customer

A Sales rep checks pipeline in one report. PreSales pulls deal detail from another tab. Marketing builds a campaign ROI dashboard. Customer Success cross-references renewal and case reports by hand every Monday morning. All four are describing the same underlying Salesforce org — just through different, disconnected views of it.

Every one of those views takes a login, a click path, and a mental switch away from the actual conversation someone's trying to have — with a customer, a manager, or a teammate.

This project asks a simple question: what if the CRM answered you directly, in plain language, inside the conversation you're already having — instead of the other way around?

THE SOLUTION

One MCP server, two ways to run it

Built on Anthropic's Model Context Protocol — an open standard for connecting an AI assistant to real, live data. Claude doesn't get a snapshot or a training-time guess about your Salesforce org; it calls the same REST API your browser does, with your own OAuth session, in real time.

WHAT YOU CAN ACTUALLY ASK — SALES & PRESALES

Real conversations, not a feature list

Sales

  • Summarize open pipeline by stage, with deal count and total amount per stage
  • Rank the biggest open deals by amount, with owner and close date
  • See what's likely to close in a given window — a rolling forecast, not a static report
  • Triage new leads by source and status
  • Log a call note straight back to Salesforce as a Task, from inside the conversation
“Summarize my pipeline by stage, then show me the 10 biggest open deals.”
“What's likely to close this month?”

PreSales

  • Pull full deal context before a call — stage, next steps, and who's actually involved on the customer side
  • See exactly what's quoted, product by product, so the demo matches the deal
  • Get the entire account picture in one shot — open deals, cases, contacts, recent activity — before a QBR
“Give me everything on the Acme deal before tomorrow's call.”
“What's actually being quoted on this opportunity?”

Marketing

  • Who actually showed up to a campaign, and their member status
  • Which lead source is converting best right now, not last quarter

Customer Success

  • Open cases by priority, the first thing to check every morning
  • What's renewing in the next 60 days, or whatever window matters
  • At risk accounts — low probability renewals cross referenced with open high priority cases, ranked by deal size
“Which accounts are at risk in the next 60 days?”
“Give me a fast health check on this account before I call them.”

Every tool is documented for what it's built on — standard Salesforce fields where possible, with a clear note on where an org's custom fields (health score, NPS, renewal risk) need one small addition. The project ships with a contributor's guide for exactly that.

Salesforce Cloud MCP Server 05
HOW IT'S BUILT

Engineered to be extended, not just used

  • OAuth 2.0 Authorization Code + PKCE for Sales/Service Cloud — a real browser login, a refresh token, no hardcoded credentials anywhere in source.
  • A separate, correctly-scoped connection for Marketing Cloud — it's a genuinely different Salesforce product with its own API, and the code treats it that way instead of pretending it's the same system.
  • One tool file per business function (sales, presales, marketing, customer success) sharing a single generic SOQL/REST client — adding a new tool never touches auth or another team's file.
  • Read tools and one clearly-marked mutating tool, with the convention documented so anyone contributing keeps that split visible.
  • Two runnable entrypoints, one codebase — a stdio process for local use, a Streamable-HTTP service with a health check and access control for cloud deployment, sharing every tool and client underneath.
  • MIT licensed, with a contributor's guide, an environment template, and a fictional demo dataset so anyone can try the tool shapes before connecting a real org.
